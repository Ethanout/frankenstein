## 已确认的决定

### Q20

**类型布局、游戏整数与 NBT**

- 不提供复数和四元数的默认分量名称、顺序或 NBT 布局；矩阵类型的后续调整见 Q23。
- 使用 `minecraft_int` 表达 Minecraft 整数，与数学整数 `int` 区分。
- NBT 数据使用 nbtlib。

已写入[类型补充与自定义检查](types.md)。本轮答复先确认 `minecraft_int` 名称，运算行为与 `real` 精度已由后续 Q22 确认。

### Q22

**minecraft_int 运算与 real 精度**

**答复原文：**

> 带minecraft变量的完全模拟mc内部变量运算机制
> real按数字精度来，也就是数学意义上精确的数，而不是估计值

已确认：

- 涉及 `minecraft_int` 等 Minecraft 类型的运算，完整模拟对应的游戏内部机制，包括溢出、取整、除法和余数，不限于加、减、乘。
- `real` 表示数学意义上的精确实数，不使用有限浮点精度或默认容差代替其含义。

已写入[类型补充与自定义检查](types.md)、[数值运算](expressions.md#数值运算)和形式化检查。

### Q23

**内置类型与名称复用**

已确认：

- `minecraft_` 后可以接全部 NBT 类型名称，包括数值、字符串、列表、复合标签、数组和结束标记。
- `int`、`real` 表示数学意义上的精确数字。
- 支持 Python 与 NumPy 的类型；与已有类型语义相同时，共用名称，不为来源不同而增加前缀。
- NumPy 类型名无冲突时省略 `np.`，例如直接写 `float32`；限定名 `np.float32` 仍表示同一类型。语义不同的同名类型保留限定名。
- 矩阵使用 `ndarray`，按需说明形状和元素类型，不另设固定大小的矩阵类型。

已写入[内置类型](types.md#内置类型)和[名称规则](lexical.md#名称)。

### Q24

**NBT 数值的运算上下文与混合类型运算**

NBT 规定数据格式，但不为每种标签提供独立的四则运算。例如，`Byte` 数据可以读入记分板计算，再转换写回；结果同时取决于记分板运算和写回转换。

待补充：

- `minecraft_byte`、`minecraft_long`、`minecraft_float` 等参与表达式运算时，怎样指定对应的游戏操作及读写转换？
- 不同 Minecraft 数值类型混合，或与 `int`、`real`、Python、NumPy 数值混合时，采用什么类型提升和运算规则？是否需要显式转换？

当前处理：已明确的记分板运算按 Q22，Python 或 NumPy 已定义的类型提升按相应环境规则；其他运算缺少必要上下文或混合类型规则时，报告未检查，不自行推定转换、溢出或精度规则。
