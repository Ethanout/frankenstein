# 注释与换行

自然语言说明可以直接与表达式混写，用换行拆分较长的表达式。Markdown 中可以用 `frank` 代码块标记这些内容；放入函数头文档的方式见[函数头文档](../style/function-docs.md)。

## 直接写说明

工具自动识别时，只有完整解析为 frank 表达式的内容才进入后续检查。解析失败时，原文保留为说明。括号内的多行内容合在一起解析，整条解析失败时，不从中抽取部分行继续检查。

疑似表达式错误的提示、明确检查时的要求见[自动识别与明确检查](checking.md#自动识别与明确检查)。

## 注释

frank 只用 `#` 标记注释。工具不尝试将注释解析为表达式；多行注释需要每行加上 `#`。

```frank
# 自然语言说明可以放在注释里。
x = score(@s xx)  # 取得输入值。

# 多行说明可以逐行加上 #。
# 这些内容不参与条件求值。
x >= 0
```

`#` 从当前位置注释到行尾。`//` 只表示向下取整除法，不作为注释标记。

字符串、选择器、记分项名和 NBT 路径等位置参数内部的 `#` 不作为 frank 注释。例如，`score(#damage demo)` 中的 `#damage` 是记分项名。嵌入的 Python 代码按 Python 自身的注释和字符串规则解析。

## 括号与换行

括号必须成对且正确嵌套。括号内可以换行，继续书写同一条表达式；括号外的换行表示表达式结束。不使用反斜杠续行。

建议续行缩进四个空格，闭括号与该表达式的起始缩进对齐。

```frank
x = score(@s xx)
(
    x >= 0
    and x <= 46340
)

score(
    @s
    xx
)
```

第二个例子中，`@s` 和 `xx` 仍是两个参数。选择器和 NBT 路径内部的括号按 Minecraft 语法处理，参数内部不得任意插入空格或换行。注释和字符串中的括号不参与 frank 的括号配对；嵌入的 Python 代码单独按 Python 语法解析。

## 其他书写约定

### 名称

名称由英文字母、数字和下划线组成，不能以数字开头。同一片段中的名称不得重复定义，使用前先定义。

以下为保留名称，不能用于普通名称定义：

```text
true false and or not
score storage entity block tag exists abs
add_type py python py_def
any bool str string int real float complex quaternion
list tuple dict set frozenset bytes bytearray memoryview range slice object type
np
```

其他已提供的内置类型名也不能用作普通变量名，常用写法见[内置类型](types.md#内置类型)。

普通名称和自定义类型名不带点号。NumPy 类型可以写成 `np.float32`，不冲突时也可省略 `np.`，写成 `float32`。数据位置内部的点号仍按 Minecraft 的名称或路径规则解释。

自定义类型名的约束见[类型补充与自定义检查](types.md#自定义类型)。

### 数值与字符串

`true`、`false` 表示布尔值。整数和有限小数使用十进制写法，例如 `12`、`0.5`；数值前的 `+`、`-` 作为运算符处理。普通字符串使用双引号和 JSON 字符串转义规则，例如 `"player"`、`"line\nnext"`。

普通字符串不跨行。多行说明可以直接分行书写，需要明确标记时逐行加上 `#`。复数和四元数暂不规定专用字面量。

### 运算符

识别运算符时取最长匹配，例如 `!=` 不拆成 `!` 和 `=`。运算优先级见[常用写法](expressions.md#运算优先级)。
