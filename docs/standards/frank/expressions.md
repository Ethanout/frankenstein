# 常用写法

通常只需写出数据位置。需要进一步说明时，再添加名称、类型或条件。

## 数据位置

| 写法 | 含义 |
| --- | --- |
| `score(<记分项> <记分板>)` | 一个记分板值 |
| `storage(<storage ID> <NBT 路径>)` | storage 中的数据 |
| `entity(<选择器> <NBT 路径>)` | 实体上的数据 |
| `block(<x> <y> <z> <NBT 路径>)` | 方块上的数据 |
| `tag(<选择器> <tag 名>)` | 实体是否具有指定 tag，结果为布尔值 |

括号内不同项用空格分开。选择器或 NBT 路径内部的逗号、引号及括号保留原有含义，按项目声明的 Minecraft 版本解释。

数据位置可以独立写出，不必给它起名或指定值：

```frank
storage(demo:io character.damage)
score(@s demo.health)
```

单独列出位置，说明文档关注哪项数据。需要说明它的取值或变化时，再补充条件。`tag(...)` 直接表示是否具有指定 tag。

例如，`score(player.level demo)` 与[类与存储布局](../style/storage.md)中的 `score player.level demo` 指向同一位置。

## 名称定义

后文需要引用某项数据时，用 `名称 = 表达式` 给它起名：

```frank
damage = storage(demo:io character.damage)
```

`=` 给文档中的值起名，`==` 表示相等条件。位置参数内部的 `=` 保留原有含义。

名称保留定义时读取到的值。即使该位置的值后来改变，已定义的名称仍表示原来的值。同一片段中，名称不得重复定义，使用前先定义。头文档中的名称使用范围和取值时机见[函数头文档](../style/function-docs.md#使用-frank-表达式) D10。

## 可选类型

需要明确数据类型时，把类型写在名称前。省略类型等价于 `any`：

```frank
minecraft_int damage = storage(demo:io character.damage)
```

`minecraft_int` 表示游戏整数，`int`、`real` 表示精确的数学整数和实数。还可以使用其他 `minecraft_*` NBT 类型、Python 类型及 `float32` 等 NumPy 类型。完整含义及自定义类型见[类型补充](types.md)。

## 逻辑条件

需要说明取值要求时，直接写出条件。以下假设 `damage` 已定义：

```frank
damage >= 0
```

`+`、`-`、`*`、`/` 用于数值运算；`<`、`<=`、`>`、`>=`、`==`、`!=` 用于比较。条件也可以连写，例如 `0 <= damage <= 100`。

多个条件可以用 `and`、`or`、`not` 组合：

```frank
damage >= 0 and (damage <= 10 or damage == 20)
not (damage == 13)
```

也可以使用等价的符号写法：

```frank
damage >= 0 && (damage <= 10 || damage == 20)
!(damage == 13)
```

`and`、`or`、`not` 及其符号写法只能用于布尔条件。非零数值、非空字符串或独立的数据位置声明，不会自动转换为“成立”。

同一片段中分别写出的多条布尔条件都需要成立，相当于用 `and` 连接。名称定义和独立的数据位置声明不作为条件参与判断。

检查时缺少数据所产生的未知结果，按[检查结果](checking.md#条件与未知结果)处理。

## 存在性

`exists(数据位置)` 检查一个位置是否存在，参数为 `score`、`storage`、`entity` 或 `block` 位置。

```frank
exists(storage(demo:io player.level))
```

已提供所需游戏状态时，记分项或 NBT 路径不存在，结果为不成立；未提供所需状态时，结果为未知。值为 `0` 与不存在是两种情况：已有且值为 `0` 的记分项仍然存在。

## 运算细节

### 数值运算

`int`、`real` 按精确数学值运算，整数、有限小数和分数均保留精确值。`real` 不使用有限浮点精度，也不默认以容差判断相等。

对于这些数学数值，`/` 为除法，`//` 为向下取整除法，`%` 满足 `a == (a // b) * b + a % b`，其中 `b` 不为零。例如，`-7 // 3 == -3`，`-7 % 3 == 2`。`abs(x)` 返回数值 `x` 的绝对值。

涉及 `minecraft_int` 的运算完整遵循目标 Minecraft 版本的记分板整数规则，包括加减乘、除法、余数、取整、溢出和运算失败。`/` 和 `//` 都按记分板整数除法计算，`%` 按记分板取模计算。每一步中间结果及后续运算也使用游戏规则。

例如，以下条件均成立：

```frank
int a = 2147483647
minecraft_int b = 2147483647
a + 1 == 2147483648
b + 1 == -2147483648

real x = 0.1
x + 0.2 == 0.3
```

检查器无法确定某项运算对应的游戏规则，或尚未支持该规则时，报告未检查，不退回普通数学运算。无法精确判断 `real` 条件时，同样报告未检查，不自行用近似值或默认容差代替精确比较。

其他 `minecraft_*` 类型按所描述的具体游戏操作计算，不一律套用记分板整数运算；类型写法见[内置类型](types.md#内置类型)。

`float`、`complex` 的数值运算按 Python 规则处理；`float32`、`int64` 等类型按对应 NumPy 版本处理，包括精度、舍入、溢出，以及不同类型共同运算时的转换规则。这些类型不按 `real` 的精确实数规则计算；逻辑条件仍须为布尔条件。

不同类型共同运算时，Python 或 NumPy 已定义的转换按各自规则处理。涉及游戏类型、精确数学类型等且转换规则尚未确定时，不自行选用其中一方的规则，待补充事项见[混合类型运算](questions.md#q24)。

声明四元数或自定义类型，不会自动为它定义运算规则。已知类型不适用的运算报告错误；规则尚未定义或工具尚未支持的运算报告未检查。

嵌入的 Python 代码始终按 Python 及其所用库计算，不套用 frank 的数学数值或游戏运算规则。

### 运算优先级

以下从高到低排列。同一级的二元算术运算从左到右结合；括号可以改变分组。

| 顺序 | 运算 |
| --- | --- |
| 1 | 括号分组、数据位置、`exists(...)`、`abs(...)` |
| 2 | 一元 `+`、`-` |
| 3 | `*`、`/`、`//`、`%` |
| 4 | `+`、`-` |
| 5 | `<`、`<=`、`>`、`>=`、`==`、`!=` |
| 6 | `not`、`!` |
| 7 | `and`、`&&` |
| 8 | `or`、`\|\|` |

`&&` 等价于 `and`，`||` 等价于 `or`，`!` 等价于 `not`，优先级均按本表解释。混用与、或运算时，建议用括号明确分组。

`0 <= x <= 46340` 等价于 `0 <= x and x <= 46340`。`=` 用于整条名称定义，不参与上述优先级。
