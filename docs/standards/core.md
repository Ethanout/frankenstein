# Frankenstein 通用协作规范

不同作者的数据包要放在一起运行、互相调用时，只需遵守这一页。包内部怎么命名、怎么组织，由作者自己决定。

标有〔检测 N〕的规则可以由工具检查，N 是开始报告的检查等级，见[规则怎么读](README.md#规则怎么读)。

## 不打架

**C1 · 必须** 自建的记分项、实体 tag、storage、bossbar、队伍等名称以自己的命名空间开头，如 `demo.health`、`demo:player`。〔检测 1〕

例外：公共库可以把不带前缀的名称（如 `int`、`res`）声明为接口，并在库文档中登记。调用这个库的包按接口使用这些名称。工具对未登记的无前缀名称给出警告。小豆 MOT 框架的公共名称另有规范，之后单独收录。

`/trigger` 用的记分项要让玩家手打，可以用不带命名空间的短名，但要在 frank.txt 中用 `trigger <名称>` 声明，未声明时 2 级警告。不同作者用了同一个短名仍会冲突，声明只用来提醒。

**C2 · 应该** 前缀与名称之间用 `.` 分隔，名称用小写蛇形：`demo.max_health`。〔检测 2〕

**C3 · 必须** 写明包占用的世界资源：常加载区块、固定 UUID、工作实体、工作坐标、修改的游戏规则。〔检测 2〕

使用 frank.txt 时，固定 UUID 的世界实体和常加载区块用 `world_entity`、`forceload` 声明，见 [frank.txt](#franktxt)。

**C4 · 应该** 手写的固定 UUID 不使用版本号 4，即第三段的首位不是 `4`，避免和游戏生成的 UUID 相撞。〔检测 2〕

**C19 · 应该** 手写的固定 UUID 以项目自己的前缀开头，并在 frank.txt 中用 `uuid_prefix` 声明。不同项目不用同一个前缀，例如 Bookshelf 用 `B5`。〔检测 2〕

**C16 · 应该** 数据包创建的实体加 `smithed.entity` tag；不希望其他包修改的实体再加 `smithed.strict`。

**C17 · 不得** 修改其他包带 `smithed.strict` tag 的实体。

## 能互相调用

**C5 · 必须** 在包的说明文档里列出接口清单：路径、用途，以及它是普通调用还是由框架回调。

可以在包根目录另放一份 `api.txt`，每行一个资源位置，`#` 开头为注释，供工具读取。C7 的检测依赖这份清单。

```text
version 1.4.2

# demo 的接口
demo:character/hurt
#demo:character/update
```

普通接口和封装接口都写进清单，都受 C12 的版本约束。

**C6 · 必须** 每个接口写明以下内容，写法随意（自然语言、[frank](style/function-docs.md) 均可）：

- 执行者和位置要求；没有要求时写“无要求”
- 输入：位置、类型、倍率和单位
- 输出：位置和含义
- 会改写的数据和其他副作用
- 带回调的接口：回调期间能读到哪些数据、放在哪里、何时失效；名称由开发者决定

**C7 · 不得** 调用其他包接口清单以外的函数，也不得读写清单以外的数据。〔检测 1〕

**C8 · 必须** 调用者只依赖文档里写明的输出。共享的返回位置（如 `res int`）要在下一次调用前取走。

**C18 · 必须** 封装接口（给调用者用的、负责校验输入的入口）在同一个项目里只用一种形式，并在 frank.txt 中声明。〔检测 1〕

| 声明 | 形式 |
| --- | --- |
| `api_form tag` | `#ns:class/method` |
| `api_form api` | `ns:api/xxx` |
| `api_form underscore` | `ns:class/_method` |

## 可预期

**C9 · 必须** 临时数据不跨 tick。跨 tick 的数据放在自己的命名空间里。

**C10 · 应该** 初始化通过 `#minecraft:load` 或 Lantern Load 进入，重复 `/reload` 不出错。用其他方式初始化时，在包文档中写明。〔检测 2〕

**C11 · 必须** 写明支持的 Minecraft 版本和依赖的包。

## 版本与生命周期

**C12 · 必须** 写明包的版本号，格式为 `主.次.修订`。使用 `api.txt` 时，写在开头的 `version` 行。〔检测 2〕

| 变化 | 升级 |
| --- | --- |
| 删除接口，或改变已有接口的输入、输出、执行要求 | 主版本 |
| 新增接口，或给已有接口加可选输入 | 次版本 |
| 只修 bug，接口说明不变 | 修订 |

只有接口清单里的接口受这张表约束，其他函数随时可以改。`0.x` 是开发期，不受约束。

**C13 · 应该** 删除接口前先标记弃用，写明替代接口和预计删除的版本，至少保留一个次版本后再删。用 frank 写头文档时，用 `@deprecated` 标签。〔检测 2〕

调用已弃用的接口时，工具给出警告。

**C14 · 应该** 提供卸载入口，删除本包创建的记分项、storage、常加载区块和实体，并写进接口清单。共用的世界实体由提供它的库删除，其他包的卸载入口不删。

**C15 · 应该** 包更新后，由包自己迁移存档中的旧数据。

## 面向玩家

**C20 · 应该** 玩家看到的文本用翻译组件，键名以命名空间开头，并写 `fallback`（1.19.4 起），没有资源包时也能显示。

```mcfunction
tellraw @s {"translate":"demo.player.welcome","fallback":"欢迎！"}
```

**C21 · 应该** 调试信息只发给带 `<ns>.debug` tag 的玩家。

**C22 · 不应** 在会显示给玩家的记分项（侧边栏、玩家列表、名字下方）上存放内部用的假玩家。不得不放时，假名以 `#` 开头，这样不会显示。

## frank.txt

frank.txt 是 frank 检查工具的配置文件，放在包根目录（`pack.mcmeta` 旁）。每行一条声明，`#` 开头为注释：

```text
# 检查等级 1–3；命令行参数优先，都没写时为 2
level 2

# 采用 Frankenstein 项目规范；没有这一行时只按通用规范检查
style frankenstein

# 封装接口的形式，见 C18
api_form tag

# 固定 UUID 的前缀，见 C19
uuid_prefix c0ffee

# 世界实体：world_entity <UUID> <实体类型> <维度>，见 C3
world_entity c0ffee-0-0-0-1 minecraft:marker minecraft:overworld

# 常加载区块：forceload <维度> <区块 x> <区块 z>
forceload minecraft:overworld 1874998 790527

# 不带命名空间的 /trigger 记分项，见 C1
trigger menu
```

项目规范另有 `const`、`special`、`extern` 三种声明，见[项目规范](README.md#franktxt-中的项目声明)。

## 不在核心范围内

下面这些由各包自己决定，可以选用一套现成的风格，例如 [Frankenstein 项目规范](README.md#frankenstein-项目规范)：

- 模块怎么划分（项目规范按类，小豆按带 `.doc.mcfo` 的目录）
- 下划线前缀表示什么（私有、成员方法还是对外接口）
- 模块入口的名字（空名函数、`main`、`init`）
- 临时变量和常量的写法（`#a`、`#temp_a`、`#CONST`）
- 类名大小写、storage 内部布局、目录深度
- 输入输出放在哪（`<ns>:<class>`、`<ns>:io input`、`"<操作名>".input`）

不采用项目规范的包，要保证接口清单（C5）和接口说明（C6）与实际行为一致。做到这一点，调用者就不需要知道上面这些细节。
