# 命名和架构规范 - 轩宇版

## 前言

本规范一般用作个人作品或碎钻Minecraft作品使用。

规范只是一套约定，不会被游戏检查。

本规范不一定是 **好用的**, 主要目的是使同一个项目中的命名和架构风格保持一致。

## 数据包

### 合法性

本小节为合法的标识符作说明，以防误解。同时，这里的 **应该/不应该做** 优先级最高

- **函数名** : 函数名只允许小写英文字母 (a-z)、数字 (0-9)、下划线和 _点号 (.)_，或为空。所以函数只允许蛇形命名。

在 `minecraft` 命名空间下目录 `foo` 内的空名称函数 `.mcfunction` 可以通过这样的方式引用 `minecraf:foo/`，这与 `foo.mcfunction` 的引用 `minecraft:foo` 不同。

- **SNBT 键名** : 允许所有字符串。但是一般不推荐使用除了英文字母、数字和下划线以外的字符，不推荐用数字开头。

- **标签 (Tags) 名** : 允许保存所有字符串，并看作一般的字符串 SNBT 一样检查。但 `/tag` 命令和目标选择器 `tag` 只允许使用英文字母、数字和下划线，且不允许使用引号表示通用字符串。

### 通用标识符约定

通用标识符约定是从众多高级语言程序设计中借鉴的

1. 注意 `#`, `#temp_` 前缀和 `_x(\d+)`, `_b(\d)`, `_E`, `_M` 后缀，它们在下文有特殊用途

2. 只使用大小写英文字母 (A-Z, a-z)、数字 (0-9)、下划线和 _点号 (.)_ 组成

3. 不以数字开头，这是为了避免与数字字面量混淆的 **洁癖** （在 Minecraft 内这样写不会造成问题）

### UUID

只讨论十六进制UUID，SNBT内的数组表示可以使用语法糖 `UUID:uuid("xxxxxxxx-xxxx-Axxx-Bxxx-xxxxxxxxxxxx")`

对UUID进行规范是为了防止与其他人使用的UUID相撞。

十六进制 UUID 表示为：xxxxxxxx-xxxx-Axxx-Bxxx-xxxxxxxxxxxx

其中 A 是版本号，B 是变种。Minecraft使用的第4版、变种1（RFC）的UUID

因此 A = 0b110，B = 0b0xx。一个不自然生成的16进制UUID应该将A的位置写为除了4以外的数字，其他位应该 **对人类来说是随机的**

### 面向过程

#### 过程

一个过程可能需要分几步执行，假设这个操作叫 `proc`，那么对应的文件结构应该是

```text
proc/.mcfunction
proc/step_1.mcfunction
proc/step_2.mcfunction
```

其中空名称函数为入口。

特别地，如果存在 `start`, 那么空名称函数用于注入特定的上下文。如：

```mcfunction
# proc/.mcfunction
execute in minecrat:overworld positioned ~ 0 ~ run function proc/start
```

#### 转发

有时候需要根据一个状态转发不同的函数，那么就需要做一个转发器

```text
proc/.mcfunction // 转发器
proc/var1/.mcfunction // 变种入口
proc/var2/.mcfunction // 变种入口
```

### 面向对象

#### 属性

在 SNBT、记分板名称、标签 Tags 中使用面向对象思维设计数据包时，可以采用这样的约定。

类使用大驼峰命名，属性使用小驼峰命名。

假如有一个类 Class，它的属性 attr 应该写为 `Class.attr`

#### 方法

为了表明这是一个方法，需要将函数放在 `<类名>/` 目录下，由于函数名称的限制，这里只能使用蛇形命名。

当表示成员方法时，用一个下划线 `_` 起始命名。当表示静态方法时，不需要额外的起始符。对私有成员方法/私有静态方法的约定见下文。

#### 实例化

类的实例化指通过类创建一个实体（组/树）或一段数据，类的实例化函数应该命名为

```text
class/new
```

当实体作为一个类的实例时，需要特别的标签来表示。

假如一个 **实体组/实体树** (多个实体组成的对象) 是类 `Class` 的实例，那么应该有且仅有一个实体组中的实体拥有 `Instance.Class` 标签，所有的实体都应该拥有 `Class` 标签。

该类的成员方法应该是以 `Instance.Class` 对应的实体为执行者设计的。

#### 私有

如果这个函数是私有的，那么就用两个下划线起始 `__func.mcfunction`

私有意味着这个函数需要明确的执行环境，只对一个模块负责。

如果这个函数是私有成员方法，使用点号起始的方式命名 `.func.mcfunction`

#### 世界实体

操作世界实体的函数需要比一般的私有函数更高的安全性，因此世界实体有自己的类 `Global`，操作世界实体的函数是这个类的成员方法。世界实体的使用必须保证维度安全和实体安全。调用世界实体成员方法的行无论在哪个维度，哪个坐标下，都要保证世界实体执行前后在同一个维度，同一个区块，且该维度的该区块必须被强制加载。成员方法内仅使用 @s 选中自己。

常用的子类有 `Global.Text` (用于解析动态文本组件), `Global.Item` (用于转发物品)，`Global.UUID` (用于转发UUID)

```text
global/_get_vector/.mcfunction // 用于设置安全上下文
global/_get_vector/start.mcfunction
```

#### 实例管理

如果项目内有可实例化为实体的类设计，那么应该有管理所有对象ID的记分板。如果实例化为 storage 数据，应该存放在专门的列表内。

实例管理本身作为一个类 `Instance` 设计。

下面是一个基本的 `Instance` 设计：

```text
instance/_get_id.mcfunction
instance/_finalize.mcfunction
instance/_finalize_id.mcfunction
```

`instance/_get_id` 用于返回一个不重的整数 ID，`instance/_finalize` 用于删除与执行者同 ID 的实例，并调用目标实例的 `_finalize` 方法（若存在）。`instance/_finalize_id` 是一个宏函数，用于删除给定 ID 的实例，并调用目标实例的 `_finalize` 方法（若存在），这个函数应该适用于实例不是实体的情况。

storage 实例应该存储在命名空间 ID 为 `Instance:<类名>` 的 storage 内的 data 列表内。每个实例的数据用一个复合标签存储，并带有整型子字段 `instanceID`

### 计分板

#### 记始化

使用一定的缩进来书写初始化。

例：

```mcfunction
scoreboard objective add foo dummy
    scoreboard players set var1 Const 1
    scoreboard players set var2 Const 2
    scoreboard players set var3 Const 3
```

#### 临时变量

临时变量应该用 `#temp_` 起始。

#### 常量

常量应该使用 `#` 起始，并全大写。

#### 数字字面量

数字字面量通过这样的方式初始化。

```mcfunction
scoreboard objective add Const dummy
    scoreboard players set -1 Const -1
    scoreboard players set 0 Const 0
    scoreboard players set 16 Const 16
```

#### 高精度

最小分度值小于1的量应该以 `_x<相对于精度1的放大倍数>` 为后缀，例如 `health_x10` 是最小分度值为 `0.1` 的数据。

#### 大数

> 大数一般存储进 storage，只在必须时应用这条规范。

用多个分数拼接大数据时应该以 `_b<顺序>` 为后缀，例如 `health_b0` 表示 `health` 数据的第一部分（低位）。

> 高精度高范围 `health_x10_b0`

#### 浮点数

> 浮点数一般存储进 storage，只在必须时应用这条规范。

分开存储尾数和指数时 `_M`, `_E` 分别用于表示尾数（带符号）和指数位。

#### 虚拟分数持有者

如果实体（特别是玩家）会获得分数，那么该记分项下就不应该存储不包括特殊符号的虚拟分数持有者。常用的特殊符号为 `#`, `$`, `.` 等。进一步，这些分数持有者应该和玩家获得分数的行为有关，否则应该放到别记分项下。

### 临时变量

临时变量必须在本操作完成后释放，不可跨tick。

### 输入输出

除了宏参数输入外，输入参数在 storage 内的格式应该是

```json
{
    "操作的完整名称":{
        "input":{
            "arg1":1,
            "arg2":2
        }
    }
}
```

如

```json
{
    "Math.cross":{
        "input":{
            "v1":[1.0, 0.0, 0.0],
            "v2":[0.0, 1.0, 0.0]
        }
    }
}
```

运行后，输出为

```json
{
    "操作的完整名称":{
        "output":{
            "result1":1,
            "result2":2,
        }
    }
}
```

如

```json
{
    "Math.cross":{
        "output":{
            "v":[0.0, 0.0, 1.0]
        }
    }
}
```
